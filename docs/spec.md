## 2. Постановка задачи (цели, задачи, общее описание)
**Что указывать в этом разделе**:  
- **Цель** — какую проблему решаем, какое улучшение планируем достичь.  
- **Задачи** — перечень ключевых задач, необходимых для достижения цели.  
- **Общее описание** — краткое объяснение текущей ситуации и предстоящих изменений (с точки зрения бизнеса/логики).

**Пример**:
> **Цель**: Упростить работу отдела закупок за счёт чёткого учёта поставщиков и автоматических обновлений их данных.  
> **Задачи**:  
> - Создать в 1С отдельную сущность «Поставщики» для хранения контактных и финансовых данных.  
> - Реализовать обмен с внешней системой снабжения SupplyChainPro.  
> - Организовать разграничение доступа к редактированию, оставить его только у менеджеров закупок.  
> - Предусмотреть тестирование корректности загрузки и роли.  
>
> **Общее описание**:  
> Сейчас для ведения поставщиков используется общий справочник контрагентов. Данные нередко устаревают, так как нет автоматического обновления. Планируется создать отдельный справочник «Поставщики» и настроить периодическую загрузку информации по ИНН из SupplyChainPro. Также будет расширен функционал документов, связанных с закупками, чтобы выбрать поставщика из нового справочника.

> **Назначение раздела**: описать **что** будет реализовано, **какие** объекты 1С для этого создаются или меняются, и **кто** из пользователей (какие роли) имеет к ним доступ.  
> 
> **Подход к оформлению**:

>   1. Функциональное назначение (зачем нужен).  
>   2. Реквизиты (структура, таблицы, если есть).  
>   3. Важные моменты реализации (например, проверка уникальности ИНН).  
>   4. Права доступа (какие роли могут просматривать, редактировать).  
>   5. Связи с другими объектами (например, при проведении документа пишем, что он делает с регистрами).

### 3.1. Справочник «Поставщики» (новый)
1. **Назначение**: хранение информации о поставщиках (наименование, контакты, банковские и прочие данные), а также их рейтинг, импортируемый из внешней системы.  
2. **Структура (реквизиты)** — в виде таблицы:

| **Реквизит**     | **Тип**       | **Описание / Комментарий**                                        |
|------------------|---------------|--------------------------------------------------------------------|
| Наименование     | Строка(150)   | Полное название поставщика                                        |
| ИНН              | Строка(12)    | Уникальный идентификатор; служит для сопоставления с внешней БД   |
| КонтактноеЛицо   | Строка(100)   | Имя или должность основного представителя                         |
| Телефон          | Строка(20)    | Телефон (формат не жёстко контролируем, ввод свободный)           |
| Адрес            | Текст или Строка | Почтовый адрес                                                    |
| УсловияОплаты    | Перечисление  | Предоплата / Отсрочка / Другое                                    |
| Рейтинг          | Число(1..5)   | Рейтинг, загружаемый из SupplyChainPro                            |

3. **Формы и функциональность**:  
   - **Форма списка**: отображает поля (Наименование, ИНН, Телефон). Предусмотрен быстрый поиск по ИНН и Наименованию.  
   - **Форма элемента**: при записи проверяется уникальность ИНН. Если совпадает с уже существующим поставщиком — выводится предупреждение.  

4. **Права доступа** (если нужно):  
   - **Роль «Менеджер по закупкам»** — может создавать, редактировать и удалять записи справочника.  
   - **Роль «Просмотр контрагентов»** — только чтение.  
   - **Администратор** — полный доступ по умолчанию.  

5. **Связи с другими объектами** (если применимо):  
   - Документ «ЗаказПоставщику» (см. ниже) будет ссылаться на справочник «Поставщики» вместо общего справочника контрагентов.  

---

### 3.2. Документ «ЗаказПоставщику» (существующий, изменяется)
1. **Назначение**: используется для оформления заказов поставщику; необходимо доработать, чтобы выбирать поставщика из нового справочника.  
2. **Новые / изменяемые реквизиты**:  
   - **Поставщик** (Ссылка на справочник «Поставщики») — заменяет существующее поле «Контрагент».  
   - **СуммаЗаказа** (Число, 15.2) — уже есть в конфигурации, без изменений.  
   - **ДатаОплаты** (Дата) — существующий реквизит, остаётся.  

3. **Формы и функциональность**:  
   - **Форма документа**: При выборе поставщика пользователь видит список из «Поставщики», а не «Контрагенты».  
   - **Проведение**:  
     - Записи в регистрах не меняются, кроме того, что теперь ссылка идёт на «Поставщики» вместо «Контрагенты».  
     - При проведении документа можно проверять рейтинг поставщика, если рейтинг < 2, выводить предупреждение.  

4. **Печатные формы** (если необходимо):  
   - «Форма заказа» (стандартная). Дополнить выводом наименования поставщика и его контактного лица.  

---

### 3.3. Обработка «ОбменПоставщиками» (новая)
1. **Назначение**: загрузка и обновление данных поставщиков из внешней системы снабжения SupplyChainPro.  
2. **Логика работы**:  
   - Запуск по расписанию (регламентное задание, например, в 06:00) или вручную.  
   - Отправка HTTP-запроса к `https://api.supplychainpro.local/suppliers` с параметром `lastUpdateDate`.  
   - Получение JSON со списком поставщиков (ИНН, Рейтинг, Контакты и т.д.).  
   - Сопоставление по ИНН: если существует, обновляем поля (Рейтинг, Телефон и т.д.), если нет — создаём новую запись.  
   - Логирование в журнал регистрации (дата, пользователь, результаты, ошибки).  

3. **Права доступа**:  
   - «Менеджер по закупкам»: может запускать обработку вручную.  
   - Администратор: полный доступ.  
   - Пользователи без соответствующих ролей: не видят обработку.  

4. **Влияние на другие объекты**:  
   - При обновлении элементов справочника «Поставщики» поле «Рейтинг» перезаписывается пришедшим значением, «Телефон» обновляется только если оно пусто или явно отличается.  

5. **Программный интерфейс**:  
   - В модуле обработке предусмотрены методы для запуска выгрузки по требованию.

---

### 3.4. Регистр сведений «ИсторияОбновленияПоставщиков» (новый)
1. **Назначение**: хранение информации о последней дате и источнике обновления каждого поставщика.  
2. **Структура** (реквизиты):

| **Реквизит**       | **Тип**                         | **Комментарий**                                           |
|--------------------|---------------------------------|-----------------------------------------------------------|
| Поставщик          | Измерение. Справочник «Поставщики» | Показывает, какой поставщик был обновлён                 |
| ДатаОбновления     | Ресурс. Дата и время    | Фиксирует момент последней выгрузки или ручного редактирования |
| ИсточникОбновления | Реквизит. Строка(50)                       | Например, «SupplyChainPro» или «Ручное обновление»        |

3. **Права доступа**:  
   - «Менеджер по закупкам»: может просматривать данные регистра.  
   - «Просмотр контрагентов»: нет прав на изменение, но доступен просмотр (при необходимости).  
   - Администратор: полный доступ.  

4. **Особенности**:  
   - Обработка «ОбменПоставщиками» при успешном обновлении записывает в регистр дату и источник.  
   - При ручном редактировании поставщика также фиксируется новая запись (можно настроить через подписку на событие «Запись» справочника).

## 5. Тестирование
**Что указывать**:  
- **Критерии приёмки**: условия, при которых доработка считается выполненной (например, все тесты пройдены, нет критических ошибок, права доступа работают корректно).  
- **Тестовые сценарии**: последовательные шаги и ожидаемые результаты.  
- **Ответственные**: кто проводит тестирование, когда и как фиксирует результаты.  

**Пример**:

| **Тест**                                         | **Действия**                                                                         | **Ожидаемый результат**                                                             |
|--------------------------------------------------|--------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------|
| 1. Создание нового поставщика вручную            | - Открыть «Поставщики» <br>- Нажать «Создать» <br>- Ввести ИНН, Наименование и пр. <br>- Сохранить | - Запись появляется в списке <br>- «Менеджер по закупкам» может редактировать       |
| 2. Запуск обмена вручную                         | - Зайти под ролью «Менеджер по закупкам» <br>- Открыть обработку «ОбменПоставщиками» <br>- Нажать «Выполнить» | - Система запрашивает данные из SupplyChainPro, добавляет/обновляет записи <br>- Регистр «ИсторияОбновленияПоставщиков» отражает изменения |
| 3. Проведение «ЗаказПоставщику»                 | - Создать документ, выбрать поставщика, ввести сумму и провести <br>- Проверить доступ без роли «Менеджер» | - Пользователь без роли «Менеджер» видит документ, но не может его изменить <br>- При некорректном рейтинге (<2) появляется предупреждение |
| 4. Проверка журнала регистрации и уведомлений    | - Остановить соединение с внешней системой <br>- Запустить обмен <br>- Проверить журнал регистрации | - Появляется запись об ошибке (нет связи), администратору уходит уведомление        |

**Критерии приёмки**:
- Все тесты пройдены успешно, нет критических ошибок.  
- Права доступа соответствуют описанной схеме (менеджеры могут редактировать, остальные — нет).  
- В журнале регистрации отражаются результаты обмена и возникновения ошибок.

## 6. Нефункциональные требования (при необходимости)
> **Примечание**: Сокращённый раздел, если в проекте есть жёсткие ограничения по производительности, безопасности, масштабируемости и т.п.

- **Производительность**:  
  - Справочник «Поставщики» до 10 000 записей, время открытия формы списка — не более 2 секунд.  
  - Обработка обмена должна успевать загрузить 500 записей за 1 минуту.  
- **Безопасность**:  
  - Хранение токена в зашифрованном виде, HTTPS при обмене.  
- **Масштабируемость**:  
  - Возможность перехода на 50 000 поставщиков без полной перестройки логики.
