# 1С конфигурация “с нуля” → в git (выгрузка в файлы)

Ниже два рабочих пути. Выбери любой — итог один: **в репозиторий попадают исходники конфигурации** (выгрузка “в файлы”), а не `.dt/.cf`.

## Вариант A: через Конфигуратор (Designer)

### 1) Создай новую информационную базу

1. Запусти **1С:Предприятие** → режим **Конфигуратор**.
2. В списке ИБ нажми **Добавить** → **Создание новой ИБ**.
3. Выбери шаблон **Пустая** (или “Создать информационную базу без конфигурации”, если доступно).

### 2) Создай пустую конфигурацию

1. Открой **Конфигурация** → **Открыть конфигурацию**.
2. Если конфигурация пустая — создай минимальный каркас:
   - **Общие** → **Общие параметры/Общие модули** (по необходимости),
   - добавь хотя бы одно изменение (например, общий модуль), чтобы было что выгружать.

### 3) Включи работу “в файлах” (выгрузка исходников)

1. В Конфигураторе выполни **Конфигурация → Сохранить конфигурацию в файлы…**
2. Укажи каталог: `./1c/src`
3. Подтверди сохранение.

После этого в `1c/src/` появится структура файлов конфигурации (XML‑представление объектов). Это и есть то, что версионируется в git.

### 4) Обратная операция (загрузить из git в ИБ)

1. Получи актуальные исходники (`git pull`).
2. В Конфигураторе: **Конфигурация → Загрузить конфигурацию из файлов…**
3. Укажи `./1c/src`
4. Затем: **Конфигурация → Обновить конфигурацию базы данных**.

## Вариант B: через EDT (1C:Enterprise Development Tools)

Общий смысл:

- в EDT создаёшь проект,
- импортируешь/экспортируешь конфигурацию как исходники,
- в git хранишь именно “исходники проекта” (а не workspace).

Рекомендации по git:

- **не коммитить** `.metadata/` (это workspace),
- остальное — по договорённости команды (многие коммитят файлы проекта, но не коммитят локальные настройки).

## Как это хранить в этом репозитории

- `1c/src/` — **единственный** источник истины по конфигурации.
- `.dt/.cf` — не коммитим (см. `.gitignore`).

## Минимальная “проверка правильности”

- После выгрузки в `1c/src/` в репозитории должны появиться новые файлы.
- После загрузки из `1c/src/` в ИБ конфигуратор не должен ругаться на “битые/неполные” исходники.
